chanx error types

Message failed validation

https://chanx.dev/errors/validation-failed

When it is sent

The frame does not match any message the consumer or topic accepts: an unknown or missing action, a payload of the wrong shape, or an envelope field of the wrong type.

What to do

Read errors: each entry names the JSON Schema keyword that failed and a JSON pointer into the frame you sent. Fix the frame and send it again. The texts in detail are for people and differ between implementations, so branch on keyword and pointer.

Example

The payload of an error frame, an RFC 9457 problem details object:

{
  "type": "https://chanx.dev/errors/validation-failed",
  "title": "Message failed validation",
  "detail": "2 validation errors",
  "errors": [
    {
      "keyword": "required",
      "pointer": "/payload",
      "detail": "Field required",
      "property": "message"
    },
    {
      "keyword": "minLength",
      "pointer": "/payload/title",
      "detail": "String should have at least 2 characters"
    }
  ]
}

Every chanx implementation sends this type the same way. The protocol spec describes the whole error format.

All chanx projects are open source. Code, issues and discussions are on GitHub.
